# v0.1.0-alpha.1（测试预发行）

第一个测试预发行：多租户 Agent 运行核心（暂未命名，仓库名 agent-runtime）。用于试跑与反馈，不要用在生产环境。

## 包含什么

- **Task Loop**：Planner → Stage → Reviewer 的固定循环；Triage 四级（fast、light、full、replan）；八种 Verdict；Atomic Node 与 Goal Node（template、tool_loop、sub_agent、sub_task）；quality 与 reasoning。
- **持久执行**：Temporal 上的 Session 与 Task 工作流，重放测试与 golden 事件历史，故障注入与恢复套件；大载荷经 Claim-Check 存到 ObjectStore。
- **Control Plane（Go）**：Task API（HTTP POST + SSE，Last-Event-ID 续传）、按租户限流与配额、提交去重、Registry（Node Template、Recipe、Model Profile、租户策略的发布、固定与影子运行）。
- **Model Gateway（Go）**：Model Profile、Tier、按“每次成功的期望成本”选档、限流、换家、BYOK、按租户计量；OpenAI 兼容适配器与离线 mock。
- **Worker（Python）**：Node Executor 与 effect 规则（幂等键、不可逆写前审批）、Policy Engine 与默认 Hook、Context Builder（五区布局、Compaction Ladder、Compaction Probe）、ToolDriver（repo、shell、web_fetch、MCP stdio）。
- **Memory Service（Python）**：作用域 ACL、写入安全与 Promotion、稠密 + 稀疏混合检索、级联删除与回滚；Postgres 行级安全，Qdrant 适配器（默认）与 Milvus 3.0 适配器。
- **Learning Pipeline**：评测 harness（开发集与留出集、多次运行取中位数、非劣效门槛）、从 trace 归纳 Recipe 的最小闭环。
- **部署与观测**：Helm Chart、OpenTelemetry Collector 配置；`scripts/dev_stack.py` 一条命令在本机拉起整套。

## 怎么试

前置：Go 1.27、uv（Python 3.13）、Temporal CLI 1.9.1；跑全部测试另要 PostgreSQL 17、Qdrant 1.19.1、Docker（Milvus 测试）。

```bash
uv sync --all-packages --locked
uv run --no-sync python scripts/dev_stack.py up --provider mock --decisions stub
uv run --no-sync python scripts/dev_stack.py token --tenant t1 --user u1
```

真模型：把 `AR_MODEL_PROVIDER_BASE_URL`、`AR_MODEL_PROVIDER_API_KEY` 写进 `~/.agentruntime/model-provider.env`，`up` 时去掉 `--provider mock --decisions stub`。命令与环境变量的完整说明见仓库根目录的 CLAUDE.md。

## 已知问题与限制

- **只有开发令牌**：没有正式登录（OAuth、SSO）。
- **执行不隔离**：Sandbox 只有本地子进程的开发实现，`shell_run` 不隔离，只能在开发环境用。
- **夜间端到端测试偶发失败**：近几天在不同用例上偶发（历史回放、重复的 task_finished、Postgres 业务库下的 Registry 版本固定）；PR 级 CI 是绿的。
- **设计书改动待落地**：默认向量库改 Milvus、数据版本固定、策略审批等七项已确认，原文还没更新（`docs/plan/design-changes-2026-10.md`）。
- **占位符**：Go 模块路径 `github.com/agentruntime/agent-runtime` 与 schema 的 `$id` 前缀是占位，定名后统一替换。
- **对照 Aster Runtime 的缺口**：见 `docs/reference/aster-runtime-gap.md`。
