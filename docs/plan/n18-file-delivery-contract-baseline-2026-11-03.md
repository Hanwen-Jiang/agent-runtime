# N-18 文件型交付前置契约基线（2026-11-03）

状态：**候选验收包，等待 S-01 人工评审**。本文把 Task/Session 最终文件交付的可验收边界固定为正反例；不修改 proto、schema、生成代码或运行时接口，也不把文件交付另建成第二套持久状态机。

## 与现有设计的共同基线

- TaskWorkflowResult 已有 `artifacts` 的对象引用列表；大载荷沿用 ObjectStore / Claim-Check，事件和工作流载荷只保存引用，不内嵌任意文件字节。
- 交付元数据候选由现有 Task、Session、tenant scope 和 ObjectStore 生命周期提供事实来源。具体 RPC、字段编号、持久化位置和下载 URL 形态必须在 S-01 后决定。
- N-18 只描述用户可取得的文件结果，不改变 Workspace 的读写权限，不自动授予网络权限，不把 SecretStore 的值作为交付内容。

## 首版候选行为

### 1. 元数据与引用

每个文件交付项至少需要可审查的非敏感元数据：`artifact_id`、显示名称、相对路径或逻辑名称、媒体类型、字节数、内容摘要、所属 tenant/session/task、创建时间和过期时间。内容本身通过 ObjectStore/Claim-Check 引用取得；引用不可被客户端改写为其他租户前缀。

响应、事件、SSE、日志和 trace 只携带元数据或受控引用，不携带文件正文、SecretStore 值、签名密钥或上游凭据。摘要用于完整性校验，不作为授权凭证。

### 2. 限制与路径

- 每次交付和每个任务分别限制文件数量、单文件字节数和总字节数；部署上限只能收窄，不能由用户文件声明放宽。
- 名称按规范化 POSIX 相对路径处理；拒绝绝对路径、空段、`..`、符号链接逃逸、保留目录和重复目标。
- 媒体类型采用允许列表或安全的未知类型回退；文件名不能决定浏览器执行语义。
- 超限或校验失败在写入和下载两个边界都返回有限错误，不留下可下载的半成品。

### 3. 授权、过期与兼容

- 下载必须同时满足调用者身份、tenant scope、任务/会话归属和文件状态；不能仅凭不可变 `obj://` 引用授权。
- 过期或撤销后，旧下载链接和旧 lease 失效；重试只能重新申请授权，不延长原文件生命周期。
- 旧客户端可继续读取原有 `artifacts` 字符串；新增元数据字段可被忽略，未知文件状态不能被当成可下载成功。
- SSE/事件先发送可重放的元数据，再发送短期下载引用或“需重新获取”提示；断线重连不重复创建文件，也不把一次性链接写入历史。

### 4. 部分失败与幂等

同一交付请求带有调用方可重放的幂等键。重复提交返回同一组已确认项，不重复计费、不重复创建业务记录；不同文件可以独立报告 `ready`、`failed`、`expired`，但总结果必须明确是否可交付，不能把部分成功静默伪装成完整成功。取消或超时后未确认对象按现有 ObjectStore 清理策略回收，不新增后台扫描器。

## 验收范围与阻塞

`tests/contract/fixtures/n18_file_delivery_contract_cases.json` 是正反例清单，`tests/contract/test_n18_file_delivery_contract_cases.py` 只检查清单完整性和本文锚点，不宣称运行时已支持 N-18。

S-01 后才允许决定 RPC/schema、下载入口、保留期和兼容性字段。真实 ObjectStore、Ingress/SSE、浏览器下载、跨会话恢复和容量/过期测试需要部署资源；资源不足时记录 `blocked_external`，不以本地静态检查代替线上验收。
