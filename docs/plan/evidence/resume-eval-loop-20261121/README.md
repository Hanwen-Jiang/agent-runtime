**简历可用表述：** 在 4 CPU / 8 GiB 的隔离环境上，用主题隔离的 60 道合成文档问题验收检索策略；将每路重排候选由 8 减为 6，检索 P95 从 2.049 秒降到 1.817 秒，保持 51/60 道命中。相比同轮无重排的 47/60 道，多命中 4 道。

同一批题的历史深度重排达到 56/60，P95 为 6.808 秒，适合优先要召回的场景。低时延配置保留为可选项，启用条件与回滚见 [RAG 复盘](rag/README.md)。本轮复用既有线上评测服务执行测试，网页、Reviewer、检索代码的本地改动均未部署。

**面试可复演案例：** 浏览器最初能按游标恢复，但流过期后的第二条路径跳过了批量历史。演示同一个注入故障的浏览器用例在 git 基线失败、在修复版通过；展示两边实际打开的事件流、恢复游标和最终页面。这个结论来自行为断言，无须把实验时长换算成线上加速比。

**SWE 端到端判分。** 选定公开的 `sphinx-doc__sphinx-8056` 与 `sphinx-doc__sphinx-9367`（均在原固定清单内，明确列题）。本轮新生成先遇到过期鉴权方式，改用该租户正式授权入口后在创建工作区时收到沙箱 503；改走隔离评测租户后，10 分钟内两个工作区仍无 HEAD 或快照，停止采集。新运行没有提交模型任务或产出补丁，因此没有新的 SWE 解决率。作为独立检查，用两份已有 rev19 补丁新跑官方 Docker 判分器，2/2 resolved，目标测试 2/2、回归测试 65/65。[新生成尝试](swe/fresh-e2e-attempts.json) · [官方重判记录](swe/official-archived-patch-regrade.json)

上述两项试验工作区的删除操作已完成，按本次 ID 对账后活跃数为 0；没有后台补丁生成或模型推理。BFCL 的五次运行已出现在[公开评测站](https://evals.cgent.link/api/capability.json)。

**下一轮优先级。** 先验工作区能在目标 base commit 上完成初始化并返回非空快照，再提交上述两题。只有两条真实预测都走完生成与官方判分后，才值得在固定实际模型与预算下扩到公开 Mini 50。工具调用的下一项候选只改“调用前校验必填字段，缺参时返回一次定向纠错”，记录修回数、额外模型轮次和费用，使用独立于本轮开发及验收的题组。检索侧将低时延配置与高召回配置分别保留，由服务的 2 秒目标决定采用哪一个。
