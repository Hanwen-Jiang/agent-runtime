三次正式运行合计 3,369 个计划样本次、1,866 份收据、633 份无错且命中目标模型的收据。已知费用至少 $85.386027，正式运行有 1,176 行费用完整性未获确认。另有校准和作废的评审预留额度尝试，均不在这笔合计内。transform 每个计划位置都有一行，其中 400 个位置直接受到额度拒绝；仪表板依据逐条收据与暂停标记展示覆盖。

## 可以如何恢复

1. 一次性冻结原始数据并停止生产者。每个 `provider-quota-pause.json` 记录原 `results.jsonl`、`run-lock.json` 哈希及首次拒绝时间；网页的只读投影再次验证来源和条数。通常的三个执行入口均实测返回退出码 75，未联系供应商。新 runner 在首次捕获真实网关额度拒绝时持久暂停，已发出的调用保留账单和收据。[断路实现](../../../../services/py-learning/src/agentruntime_learning/capability/quota.py)
2. 对 1,122 个明确遭拒且没有成功调用记录的样本次核对底账。424 个可唯一匹配真正结算为零的一笔 reservation，且同时间窗不存在未知或正费用风险。其余 698 个在原账保持待核，包含同题同模型多次重复并发所造成的歧义。另有 12 个额度故障发生前已部分返回模型结果，18 个程序停止时没有收据但有预约或支出。[零结算复核](quota-ledger-audit.md) · [公开摘要](quota-ledger-summary.json)
3. 额度恢复后，原位可安全开始的有 1,909 个，包括上述 424 个和 1,485 个没有收据、没有已见支出的原计划样本次。干净的已有观测和其他非额度错误的已有收据都保留。三份隔离副本已实际执行恢复事务、逐字节核对保留行、在不提供模型网关的情况下重建原生实验锁，分别得到 core 1,314、transform 289、judge-v2 306 个可执行位置。真实运行目录仍处于暂停。[演练](recovery-verification.jsonl)
4. 剩余 728 个先核清归属。如果在恢复经费后仍无法逐笔确定，已为这些尚未取得有效观测的位置独立生成下一次尝试的唯一身份清单，计 core 236、transform 111、judge-v2 381。执行补测前再次排除新近已判位置，按相同题号、模型、配置和旧来源留痕。每个仍缺有效观测的原位置只允许一份预先选定的独立补测，单列新增生成机会和所有支出。不能用补测覆盖原来已经有的合法成功或失败结果。此备选路径保留原待核账单，尚未发起模型调用。[补测协议清单摘要](future-attempts-summary.json)

在 cloudnium_cloud 的 `/opt/evals/deployments/capability-resume-20261123`，`python3 prepare_quota_resume.py core`、`transform`、`judge-v2` 仅做只读验算。已经确认额度恢复时，针对相应组运行 `python3 prepare_quota_resume.py <组> --confirmed-funding-restored`，再运行 `./resume_native.sh <组>`。准备命令只对固定证明涵盖的零支出槽位调整本地预算标记，保留原件；实际模型调用经独立验证的断路器。不会更改账户余额或生产默认路由。[恢复事务](prepare_quota_resume.py) · [运行入口](resume_native.sh)

恢复入口另外保存了只涉及评测、调度与预算的修正实现。三份实验的冻结题序、评测器、模型、推理档和注册表来源与停止前相同。旧归档保持原字节。断路和续跑是后续运维改进，对已取得的 633 份有效观测不主张任何质量提升。
