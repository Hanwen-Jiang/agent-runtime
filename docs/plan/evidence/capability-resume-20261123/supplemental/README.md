# 缺失观察的独立补测与同一矩阵归并

三个正式运行沿用原角色、模型、档位、评测器、题号和重复序号。首轮预算拒绝后有 728 个位置已经预先指定独立补测。上次用户暂停时另外留下 27 个预算待定或已有支出、没有最终收据的位置。将它们的停机快照、原预算文件和计费身份冻结后，正式恢复数为 755，分别为 core 248、transform 119、judge-v2 388。与另外三个原生恢复任务的题位互斥。[三份注册摘要](registrations.json)

执行器直接调用原环境中的 MatrixRunner 单题执行与评分链，启动前比较原生运行锁的全部字节。每一次独立尝试的所有网关调用共用一个新的、预定的 mx2 账本 Task ID。查询内容、被测与辅助角色、模型、推理档和租户仍取原协议。单独目录的预算与收据使该尝试能够独占执行。任一关联组发生额度拒绝时停止安排新请求，已出结果、已有支出和未决账目保留。[独立执行器](supplemental.py) · [账本核对](audit_billing.py)

逐题汇总先用原 run-lock 重建所有逻辑位置。原生已有有效判定保持原样；对预先登记的缺项采用该次独立补测的结果，包括失败，最多计一个观察。旧拒绝、同一位置已发生的部分模型响应、已知费用和未决金额保留。原始 results.jsonl 始终分别在原位和私有补测目录；公开侧的联合收据只包含计数、来源摘要和费用下界。官方组件评分由原 scorer 在去重后的全部逻辑位置上生成。付费服务停止时，不会因只有执行记录就宣布可发布。[合并投影](merge.py)
