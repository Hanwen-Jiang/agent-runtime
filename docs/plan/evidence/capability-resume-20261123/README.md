## 两种额度问题

启动 judge 时沿用 $0.50 单题上限，S-10 的模型请求在网关预留阶段就被拒绝，360 行无一次命中；另有 3 行 JudgeBench 成功记录归在该次中断原件。三个候选均能在同一网关单独命中。把正式协议的单任务预留上限设为 $8 后，三个模型在 S-10 校准各命中一次，合计记录 $0.767042，才启动新的正式比较。此上限是保护单题的预留约束，实际费用按调用返回额计算。随后发生的 403 来自供应商账户，与单题预留门槛是两个不同的故障。[准入前后证据](judge/admission-audit.json)

## 如何理解评审能力

三份候选为 Claude Opus 5.5、Claude Fable 5.1、GPT‑6 Astra，各用同一 S-10 的 40 个 Reviewer 检查点、同一 JudgeBench 的 40 个双顺序比较、同一 RewardBench 2 的 40 个评分项目，每题重复 3 次。该评审输入来自此前没有评审结果的三份现存模型配置。JudgeBench 在公开 GPT 回答对上按 seed 0 取 40 个，要求两个展示顺序都判对。RewardBench 2 五个子类各固定 8 道，33 道与同种子默认的 40 题重合；公布具体 ID，未将人工筛选的 40 题当作整个上游排行榜。S-10 自带标签和回退判定保留，草稿标签和调用污染另计。[本次精确划分](judge/cohorts.json) · [JudgeBench 作者数据卡](https://huggingface.co/datasets/ScalerLab/JudgeBench) · [RewardBench 2 作者数据卡](https://huggingface.co/datasets/allenai/reward-bench-2)

预算中断的调度改进另做了可重算的对照，用历史真实收据及固定截断位置验证覆盖，评分与覆盖各自报告。[调度协议](scheduling-protocol.md) · [历史回放](schedule-history.json) · [面试笔记](../../../../../8-legged/实验复盘/能力矩阵预算与覆盖-20261123.md)
