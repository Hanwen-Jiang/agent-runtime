## R-06 版本来源决定

当前 Registry 的修订单位是 `(scope, kind, name, version)`，没有全局修订计数。本项记录实际选中 Model Profile 的 Registry 发布修订：账本已有 `model_profile_id`，新增 `registry_scope`、`registry_revision`（真实 `vN`）与 `registry_document_sha256`。这完整标识 `platform/model_profile/<id>@vN`，不伪造全局编号。

`task-service registry-export-profiles` 从业务库一次性读取默认版本及其不可变正文，导出与 Gateway 文件兼容的 `registry_revisions` 元数据。Gateway 加载时核对每份正文摘要，价格/能力被改但版本元数据未重新导出时拒绝启动；每次重试/换候选分别冻结当次实际版本。旧文件和历史行维持未知（NULL），不开倒填。生产切换时先导出、核对与保存原 ConfigMap，再启用 `modelGateway.requireRegistryProfiles`，防止之后意外加载无来源文件。

验证：容器 `agentruntime-ci:3` 的非 root 用户执行 `go test`，`modelbudget`（含 SQLite/Postgres）、Gateway 的 `profiles/config/gateway`、task-service `cmd/task-service` 全包通过；相关包 `go vet` 与 Helm lint 通过。针对性用例覆盖真实 Registry v1→v2 导出、摘要失配拒绝、不同回退候选分别入账、旧迁移行保持 NULL。发现并修正一条 v1 遗留断言：`1a66ba4` 已取消 GLM/MiMo 的 structured 能力，测试现在明确要求这两模型不带 structured，保留其他模型的能力要求。
