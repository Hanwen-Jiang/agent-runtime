## 2. P0：先修（不改契约的部分这一次就做）

### N-01 输入引用：嵌在文字里的引用、跨 Round 的结果、deliver 的输入

挂在 S-04（Stage Runner）与 S-09（Planner）下；核心链路，同一时间只由一个 agent 改。

做法（新的运行走版本分支 `n01-references`，追加在 `patches.AT_START` 末尾；之前的历史按原路径回放）：

1. **嵌在文字里的引用**：字符串里出现的 `$<node_id>.result[.路径]`、`$task.<路径>` 换成值（字符串原样嵌入，其余写成紧凑 JSON）。
   路径不存在而 Node 的结果在时，嵌入整个结果（文字里的引用多是给模型看的，宁可多给）；Node 没有结果时这个 Node 失败
   （`unresolved_reference`），由 Reviewer 处理，不再把占位符交给模型。整串引用的规则不变（路径不存在就失败）。`$$` 仍是字面的 `$`。
2. **跨 Round 的结果**：Task 工作流记下之前各轮成功的顶层 Node 的结果（同一个 id 取最近一轮的），交给 Stage Runner。
   本 Stage 里没有这个 id 时，引用之前的结果；本 Stage 里有这个 id 时，仍然只能引用祖先（与现在一样）。`validate_stage` 与
   Planner 的校验（`planner/validate.py`）都按这条放行；Planner 的提示列出可以引用的之前的结果（id 与一行摘要）。
3. **deliver 的输入**：role 为 deliver 的 model 节点，输入里一个引用也没有时，自动带上 `upstream`：它 after 的那些 Node 的结果；
   没有 after 时带之前各轮的结果。每项最多 8000 字（截断处写明）。
4. Planner 的提示第 6 条改成能做到的写法，并说明两种引用的写法。

验收测试：`services/py-worker/tests/test_n01_references.py`（纯函数：嵌入、路径不存在、Node 不存在、`$$`、跨轮、本 Stage 同名优先、
validate 放行与拒绝；工作流：第 1 轮的结果在第 2 轮被引用、deliver 没写引用时拿到上游；旧历史回放不变）。

### N-09 Jev 接入

Jev 是 TypeSafe 的“System One”模型（`GET /v1/models`：`jev-latest`、`jev-preview`；2026-11-02 实测服务的是 `jev-1.14.0`）。
接口只有 `POST /v1/systemone`：给一段内容（`state`），一次问几个问题，问题有四种——是非（`noul`，答“是”的概率）、多选一（`choice`，
带各项概率与把握）、按量表打分（`score`）、图片里框位置（`box`）。不生成文字；一次约 1 秒；按输入 token 计费（输出不收费）。
它适合“快速、有概率的判断”，用在这几处：

1. **交付的快速检查**（这一次做了，见第 8 节）：Reviewer 要判 done 时问它交付是不是在回答、是不是在“不认自己的工具或之前的工作”。
2. 分诊的第二意见：这条消息要不要读工作区（`noul`），任务族（`choice`，带把握，把握低的再问模型）。
3. 评测的判分：DeepEval 式的量表（`score`）与 Reviewer 的 Verdict 校准（N-08、N-12）。
4. 11.14 的用户不满信号（`frustration`、`about_platform`）：不必加在分诊的模型调用里。

数据边界：发给它的是用户的消息与交付的文字（截断），不带 Task State、工具输出；密钥在 SecretStore 平台作用域的 `judge/jev-api-key`。
